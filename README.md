# 司机英语助手 · 可运行原型 v0.2

按《司机英语助手 PRD v1.1》做出来的**能直接用的原型**：司机按住说中文，松手后自动听写、翻译，并读出英文给外国乘客听；乘客端反过来，说英文、读中文给司机听。翻译有三条通道：应用方内置 Key、司机自己的 Key、离线常用表达库，任何一条断了都还能继续沟通。

配套文档：上一级目录里的 `司机语言助手PRD 1.1.docx`（第十三章至第二十章为本版新增）。

**已经上线的分享链接：** https://rebecca1017.github.io/driver-lingo/ （GitHub 仓库：[Rebecca1017/driver-lingo](https://github.com/Rebecca1017/driver-lingo)）

分享二维码见 `分享二维码.png`，可以直接发微信或打印贴在车里。

## 零、怎么发给我舅舅

把这段直接复制发给他（微信里也行）：

> 叔，你跑车遇到外国乘客，用这个：https://rebecca1017.github.io/driver-lingo/
> 点开以后，点「🇨🇳 我说中文」，按住大按钮说完松手，它会自己翻译成英文读给乘客听。乘客要说话就点「🇬🇧 Passenger」再把手机递过去。
> 要是在微信里点开的：进对话页点绿色「🎤 键盘说话」，再点键盘上的麦克风说中文，说完点「翻译」，屏幕上的英文大字直接给乘客看（微信不让网页录音，所以微信里用键盘说话）。
> 想用「按住说话」：点右上角「···」选「在浏览器打开」，打开后选「添加到主屏幕」，以后从桌面点一下就进来。

## 零之一、微信里为什么不能按住说话

微信内置浏览器不实现网页录音接口（Web Speech 识别在 WKWebView / X5 里不可用），任何网站都一样，这不是我们代码的问题。所以微信里换成两条不依赖网页录音的路径：

| 场景 | 微信里怎么做 | 是否需要额外账号 |
| --- | --- | --- |
| 说一句中文 | 点「🎤 键盘说话」→ 用手机键盘的语音输入 → 点「翻译」→ 大字给乘客看 | 不需要 |
| 说固定的话 | 点「常用表达」里的句子，直接出英文大字并按需播报 | 不需要 |
| 用「按住说话」 | 点右上角 ··· → 在浏览器打开（可加到主屏幕） | 不需要 |
| 真的想「微信里按住就能说」 | 需要做微信小程序（用微信自家的语音插件） | 需要注册小程序账号 |

## 二、放到手机上给舅舅用（必须 https）

手机浏览器只有在 **https** 页面上才允许网页使用麦克风，所以要把这个文件夹放到一个能通过 https 访问的地方。任选一种：

- **Cloudflare Pages / Vercel / Netlify**：新建项目，把这个文件夹直接拖进去（纯静态，无需构建命令），会得到一个 `https://xxx.pages.dev` 这类网址。
- **GitHub Pages**：把文件推到仓库，在 Settings → Pages 里开启。
- **自己的服务器/宝塔**：放到网站目录，配好 https 证书即可。

建议把网址**存成手机桌面图标**：iPhone 用 Safari 打开 → 分享 → “添加到主屏幕”；安卓 Chrome → 右上角菜单 → “添加到主屏幕”。这样打开就像个 App，没有地址栏，司机点一下就进来。

> 如果只能放在内网、或只能用 http 打开：麦克风会被浏览器禁止，但“常用表达”和“打字输入”依然可以正常用。

## 三、三条翻译通道

翻译按下面的顺序选用，前面不可用就自动往后落，司机端不会因为缺 Key 而卡住：

| 顺序 | 通道 | 谁出钱 | 怎么开 |
| --- | --- | --- | --- |
| 1 | 司机自己的 Key | 司机 | 司机在设置里选服务商、填 Key |
| 2 | 内置 Key（应用方提供） | 应用方 | 在 `config.js` 里填 Key，并在设置里保持开关打开 |
| 3 | 离线表达库 + 简单句式 | 不花钱 | 默认就有，永远可用 |

离线部分覆盖 **10 个场景 58 句**（迎接上车、确认目的地、路线与时间、费用与支付、等待、行李、到达与下车、车内服务、沟通困难、接机与航班）和 **16 句乘客常用表达**，再加上“多少钱、几分钟、几号出口、车牌尾号”这类简单句式的自动翻译。这些恰恰是最容易出错、也不该交给机器自由发挥的内容。

### 3.1 填应用方自己的 Key（让所有司机打开就能用）

打开 `config.js`，把 Key 填在 `apiKey` 里：

```js
window.APP_CONFIG = {
  builtinEngine: {
    enabled: true,                       // 关掉它，所有设备就只能用自己的 Key 或离线表达库
    baseUrl: "https://api.deepseek.com/v1",
    model: "deepseek-chat",
    apiKey: "sk-你的key",                 // ← 填这里
    dailyLimitPerDevice: 300              // 每台设备每天最多用多少次内置 Key
  }
};
```

填好之后，司机端不需要做任何事：设置里的“使用内置翻译服务”默认打开，首页不再提示缺 Key，用满当日额度后自动回落到离线表达库，并在设置里显示还剩余额。

**必须先知道的代价**：`config.js` 会随网页一起发给每一个打开它的人，任何拿到链接的人都能看到这个 Key，也可以拿去用。所以：

- 只给自己人和少量种子司机用，不要公开分享链接；
- 在服务商后台设置用量上限和费用提醒；
- 发现异常就在服务商后台吊销或更换 Key，前端只改 `config.js` 这一个文件；
- 正式对外前，按 PRD 第 17.5 节改成服务端代理，前端不再保存 Key。

### 3.2 司机自己填 Key

打开设置 → 选服务商 → 填 API Key → 点“测试翻译引擎” → 保存。填了自己的 Key 就优先用他自己的，费用和额度都由他自己控制：

| 服务商 | 接口地址 | 模型 | 备注 |
| --- | --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 便宜，中文场景好，推荐先用这个 |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 国内直连稳定 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | 有免费额度 |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | 国内需要网络条件 |

注意事项：

- 一次翻译都是十几个字到几十个字，一次成本大约几厘钱，正常跑一天几毛钱。
- 司机自己填的 Key 只存在这台手机的浏览器里（localStorage），不会上传到别处。
- 如果“测试翻译引擎”报跨域（CORS）错误，说明这家接口不允许网页直接调用，需要自己加一层转发（云函数），或者换成上表里能直连的服务商。
- 翻译引擎偶尔会漏掉数字。程序里内置了**数字校验**：译文数字和原文对不上时会标注“⚠️ 数字可能不一致”，请再核对一次。

## 四、怎么用

1. **司机说中文**：点“🇨🇳 我说中文”→ 按住大按钮说中文 → 松手 → 屏幕上出现放大的英文并自动读出来（点文字可以全屏放大给乘客看）。
2. **乘客说英文**：点“🇬🇧 Passenger”→ 把手机递给乘客 → 按住说话 → 读中文给司机听。
3. **不想说就点**：首页“常用表达”，改哪种场景点哪一句，直接播报；跑车时这是最快、最稳的方式。
4. **关键信息会先确认**：说到金额、地址、时间、数字、电话、航班号、目的地时，助手会先显示“我听到的是……”，司机点“✓ 对”才翻译 —— 防止把 58.6 说成 586。
5. **没听清/没网**：点“⌨️ 打字输入”，或直接用常用表达。

## 六、已验证 / 已知限制

已实测（Chrome 真机浏览器环境打开本机服务）：

- 首页、司机端、乘客端、常用表达、设置页跳转正常；
- 普通问候不打扰、金额句/地址句强制确认、确认后译文数字与原文一致（58块6 → 58.6、3号出口 → Exit 3）；
- 一键表达与常用表达点按即播报并弹出大字卡；
- 设置保存、刷新后仍在；页面无 JS 报错；
- **内置 Key 通道**：用一个本地假引擎验证了完整链路——请求带上了系统提示词、返回被正确解析、内置额度用完（3/3）后自动回落到离线表达库、设置页正确显示剩余次数；
- **数字校验**：让假引擎故意把 58.6 说成 “58 and 6”，结果卡正确弹出“数字可能不一致（原文含有 58.6）”的警告；
- 未填 Key 时的行为：首页提示可填自己的 Key，设置页显示“内置服务已打开，但应用方还没有填 Key”，翻译自动走离线表达库；
- 逻辑层 24 项单元测试（关键信息识别、中文数字解析、数字一致性、表达库匹配、离线兜底、引擎返回解析）全部通过。

还没验证 / 需要注意：

- **真机语音识别没实测过**（开发环境拿不到麦克风）。首次使用请先允许麦克风权限；如果失败，请把手机上看到的具体提示告诉开发同学。
- 浏览器语音识别会把录音发给浏览器厂商（Chrome→Google、Safari→Apple）。对隐私更敏感的话，后续可以换成自建 ASR（费用会上升）。
- 一次说话建议在 30 秒以内；太长的句子识别和翻译都会变差。
- iPhone 需要 iOS 14.5 以上；微信内置浏览器对语音识别支持不稳定，建议“用浏览器打开”。
- 自动播报依赖浏览器策略：如果没有自动读出来，点结果卡上的「🔊 播放」即可。
- 页面是单机版：两位司机的数据互不相通，也没有后台、没有账号体系。

## 七、建议的下一步

1. 真机跑一遍 iPhone + 安卓各一台，重点看：麦克风授权、自动播报是否被浏览器拦截、车内噪音下的识别率。
2. 把内置 Key 改成服务端代理，并加上设备校验与费用告警（PRD 17.5），再把链接发出去。
3. 加“乘客扫码”入口：司机贴一张二维码，乘客扫开就是乘客端（不用把手机递来递去，也更卫生）。
4. 补“纠纷话术卡”（车费争议、堵车、绕路、加价说明），这类场景司机最怕说不清。
5. 按 PRD 18.3 接入埋点，先只看“录音成功率、确认通过率、数字告警率”三个指标。
